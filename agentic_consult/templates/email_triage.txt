## Your Task

For each email, determine which rule (if any) matches based on the FULL email content (subject, sender, AND body).

### Rule Matching

- Evaluate each rule's `condition` or `match` criteria against the full email content
- Rules may have age/time conditions (e.g., "3+ days old", "5+ days old")
- For rules with `action: archive`:
  - All conditions met (including age) → respond with `archive_now`
  - All conditions except age met → respond with `archive_later`
- For rules with `action: review` or `action: track_as_task`, use that action when matched
- When multiple rules match, apply the one with highest-priority action:
  - `review` (highest - especially for VIP/Customer direct messages)
  - `track_as_task` (medium)
  - `archive_now` / `archive_later` (lowest)
- Set `rule_id` to the matching rule's ID (include rule_id even when age not met)
- If NO rule matches, use action `ask_user` with `rule_id: null`

### Audience Classification

Determine the `audience` field based on the User Identity provided in the Context:
1. **MENTION**: User is explicitly mentioned by name/nickname in the email body (Highest Priority).
2. **DIRECT**: User is on the 'To' line alone (no other To recipients).
3. **GROUP**: User is on the 'To' line with others, OR on the 'Cc' line.
4. **BROADCAST**: User is NOT on 'To' or 'Cc' lines (e.g., mailing list).

### Calendar Invites

Separate any emails that are Calendar Invites or specific scheduling requests into the `invites` list instead of `emails`.
- **Status:** 'PROPOSED' (new invite/suggestion), 'CONFIRMED' (accepted/booked), 'CANCELED'.
- **VIP Status:** Determine if sender is 'VIP' (Manager/Lead), 'CUSTOMER' (domain match), 'INTERNAL' (same domain as user), or 'EXTERNAL'.
- **Note:** Do not include these in the `emails` list.

### Actions

- **track_as_task** - Email requires follow-up action
- **review** - Email needs human attention
- **archive_now** - Archive immediately (routine email, aged enough for user visibility)
- **archive_later** - Archivable per rules, but kept visible a bit longer for user awareness
- **ask_user** - No rule matched; client agent decides with human-in-the-loop

## Guidelines

- Include ALL emails in your response (either in `emails` or `invites`, but NOT both)
- Keep reasons extremely concise (max 10-12 words).
- Start directly with the core event (e.g., 'Updates ticket status', 'Requests access').
- DO NOT start with "The email", "Email is", or "This message".
- The `reason` field should explain WHY this matched the rule - cite specific content.
- This helps the client agent decide whether to load the full email or act on the summary alone
- Do not invent rules - only apply the rules provided
